# ML-Based Intrusion Detection & Network Security Analytics (NIDS)

A machine-learning-based **Network Intrusion Detection System (NIDS)** that analyzes flow-level network data, evaluates multiple machine-learning classifiers, and provides an interactive FastAPI dashboard for **live synthetic-flow monitoring, threat prediction, model evaluation, and security analytics**.

**Live Demo:** https://ids-ml-dashboard.onrender.com  
**GitHub Repository:** https://github.com/SaswataPattanayak/ML-Network-Intrusion-Detection-System

---

## 📌 Project Overview

This project demonstrates an end-to-end machine-learning workflow for network intrusion detection and security analytics.

The system combines two intentionally separated workflows:

1. **Offline Model Evaluation** — used to train, compare, and evaluate machine-learning classifiers using held-out evaluation data.
2. **Live Synthetic-Flow Monitoring** — used to demonstrate how new network-flow records pass through the trained model, generate predictions, calculate confidence and severity, persist alerts, and appear in the dashboard in real time.

This separation ensures that synthetic demonstration traffic is **not incorrectly used to claim additional model-performance results**.

## 🏗️ Current Demonstration Architecture

The current version intentionally does **not** capture live network packets.

It does not require:

- Npcap
- Administrator/root privileges
- Physical network-interface access
- Packet-capture configuration
- Unrestricted live network traffic

Instead, the live demonstration uses synthetic network-flow records.

```text
Synthetic Network Flow Generator
            ↓
      Flow Preprocessing
            ↓
       Trained ML Model
            ↓
 Prediction + Confidence
            ↓
 Risk / Severity Classification
            ↓
     SQLite Alert Storage
            ↓
      WebSocket Streaming
            ↓
       IDS Dashboard
Live Inference Pipeline
Synthetic Network-Flow Generator
            ↓
        Random Forest
            ↓
          SQLite
            ↓
        WebSocket
            ↓
       Live Dashboard

The synthetic demonstration records use the same six model features:

Protocol
Duration
BytesSent
BytesReceived
FailedLogins
Connections

Important: Synthetic flows are demonstration inputs, not captured network traffic and not ground-truth attack records. The model prediction is what is displayed in the live demonstration feed.

🔬 Research / Model Evaluation Workflow

The model-performance sections are based on the held-out evaluation dataset generated by train_and_export.py.

Training / Test Dataset
        ↓
Preprocessing + Feature Engineering
        ↓
Six ML Classifiers
        ↓
Test-Set Evaluation
        ↓
Accuracy / Precision / Recall / F1
        ↓
Confusion Matrices + ROC/AUC

The evaluation workflow is independent of the synthetic live-monitoring pipeline.

This ensures that the reported research metrics are calculated from the evaluation dataset rather than from synthetic dashboard events.

🤖 Machine Learning Models

The project evaluates six supervised machine-learning classifiers:

Model	Purpose
Random Forest	Ensemble-based classification
Naive Bayes	Probabilistic classification
KNN	Distance-based classification
Logistic Regression	Linear classification
Linear SVM	Margin-based classification
Decision Tree	Rule-based tree classification

The exported model bundle currently identifies Random Forest as the best-performing model in the saved evaluation results.

Random Forest is therefore used as the primary model for the live inference demonstration.

🧩 Feature Representation

The final model uses six flow-level features:

Feature	Description
Protocol	Network protocol representation
Duration	Flow duration
BytesSent	Number of bytes sent
BytesReceived	Number of bytes received
FailedLogins	Failed login count
Connections	Connection count

The preprocessing pipeline reuses the fitted protocol encoder and scaler during inference so that synthetic flow records follow the same feature representation expected by the exported model.

The dashboard provides controls for the synthetic-flow demonstration.

Starts the synthetic-flow monitoring process.

1. Clone the repository
git clone https://github.com/SaswataPattanayak/ML-Network-Intrusion-Detection-System.git
cd ML-Network-Intrusion-Detection-System
2. Create a virtual environment

Windows:

python -m venv .venv

Activate the environment:

.venv\Scripts\Activate.ps1
3. Install dependencies
pip install -r requirements.txt

The current project requirements pin:

scikit-learn==1.8.0

to maintain compatibility with the exported model bundle.

▶️ Run Locally

From the project directory:

python server.py

Then open:

http://127.0.0.1:8000

The application starts the FastAPI dashboard and the synthetic-flow monitoring pipeline.

No packet-capture interface, Npcap, or --iface configuration is required for the current demonstration architecture.

🔐 Security / Deployment Scope

This dashboard is designed as a safe local and cloud demonstration of an ML-based intrusion-detection workflow.

The current version:

Does not capture real network packets
Does not inspect live network interfaces
Does not collect network credentials
Does not require administrator/root packet-capture privileges
Does not require Npcap
Uses synthetic network-flow records for live demonstration

The source and destination IP addresses used in the synthetic feed are demonstration values.

They should not be interpreted as evidence of actual network activity.

If real packet capture is introduced in a future version, it should be implemented as a separate network-acquisition layer rather than mixed with the existing model-evaluation workflow.

⚠️ Limitations

The current implementation has several intentional limitations:

Live monitoring uses synthetic network flows rather than unrestricted production network traffic.
Synthetic flows are demonstration inputs and do not represent ground-truth attack labels.
Model performance depends on the quality and representativeness of the training and evaluation data.
The current feature schema is intentionally compact for real-time demonstration.
The system is an academic/research prototype rather than a production-grade enterprise IDS.
Real-world deployment would require additional validation against representative network traffic.
The current live demonstration does not perform unrestricted packet capture.
