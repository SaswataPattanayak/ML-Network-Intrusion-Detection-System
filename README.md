# ML-Based Intrusion Detection & Network Security Analytics (NIDS)

A machine-learning-based network intrusion detection project that analyzes **flow-level network data** and presents model predictions and security analytics through an interactive FastAPI dashboard.

## Current demonstration architecture

This version intentionally does **not** capture live packets. It does not require Npcap, Scapy, administrator/root privileges, or access to a physical network interface.

Instead:

```text
Synthetic Network Flow Generator
            ↓
      Flow Preprocessing
            ↓
       Trained ML Model
            ↓
 Prediction + Confidence
            ↓
 Risk / Severity Classification
            ↓
 SQLite + WebSocket
            ↓
      IDS Dashboard
```

The synthetic demonstration records use the same six model features:

- Protocol
- Duration
- BytesSent
- BytesReceived
- FailedLogins
- Connections

Synthetic flows are **demonstration inputs**, not captured network traffic and not ground-truth attack records. The model's prediction is what is displayed in the live demonstration feed.

## Research / evaluation workflow

The model-performance sections remain based on the held-out evaluation dataset generated by `train_and_export.py`:

```text
Training / Test Dataset
        ↓
Preprocessing + Feature Engineering
        ↓
Six ML Classifiers
        ↓
Test-set Evaluation
        ↓
Accuracy / Precision / Recall / F1
        ↓
Confusion Matrices + ROC/AUC
```

This keeps the reported research metrics separate from the synthetic dashboard demonstration.

## Models

The project evaluates:

- Random Forest
- Naive Bayes
- KNN
- Logistic Regression
- Linear SVM
- Decision Tree

The exported model bundle currently identifies **Random Forest** as the best-performing model in the saved evaluation results.

## Project structure

| File | Purpose |
|---|---|
| `config.py` | Shared paths, feature schema, and dashboard/inference settings |
| `train_and_export.py` | Trains/evaluates the models and exports the model bundle plus historical dashboard JSON |
| `preprocessing.py` | Reuses the fitted protocol encoder and scaler for flow inference |
| `synthetic_flow_generator.py` | Generates model-compatible synthetic flow records without packet capture |
| `inference_engine.py` | Runs predictions, builds structured alerts, and persists results |
| `alerts_db.py` | SQLite storage for dashboard alert history |
| `server.py` | FastAPI backend, synthetic-flow pipeline, REST endpoints, and WebSocket streaming |
| `static/index.html` | Dashboard structure |
| `static/app.js` | Dashboard rendering and WebSocket feed |
| `static/styles.css` | Dashboard styling |
| `static/data/dashboard_data.json` | Historical model/evaluation data |
| `model/model_bundle.joblib` | Exported model, scaler, encoders, and metadata |

## Installation

Create/activate a Python environment and install the project dependencies:

```bash
pip install -r requirements.txt
```

## Run the dashboard

From the project directory:

```bash
python server.py
```

Then open:

```text
http://127.0.0.1:8000
```

The server automatically starts the synthetic-flow generator and ML inference pipeline. No `--iface`, `--no-sniff`, Npcap, or packet-capture configuration is required.

## Dashboard sections

### Synthetic Flow Monitoring

Displays continuously generated flow records passed through the trained model, including:

- Predicted attack class
- Source/destination IPs used for demonstration
- Protocol
- Confidence
- Severity
- Flow activity statistics

### Model Health

Shows model comparison and the best model's evaluation performance.

### Dataset View

Shows training/test class distribution and protocol distribution from the evaluation data.

### Detection Quality

Shows per-class precision, recall, F1 score, and support.

### Model Diagnostics

Shows a confusion matrix for each classifier.

### ROC Analysis

Shows ROC curves for the evaluated classifiers.

### High-Risk Predicted Events

Shows suspicious records selected from the **offline test-set evaluation data**. These should not be confused with the synthetic demonstration feed above.

## Important methodological note

The project deliberately distinguishes two data sources:

1. **Offline test-set data** — used to calculate and report model performance.
2. **Synthetic flow data** — used to demonstrate the inference pipeline and dashboard interactively.

The synthetic generator must not be used to claim additional model accuracy. It exists to demonstrate how a flow record moves through preprocessing, inference, risk classification, persistence, and visualization.

## Security / deployment scope

This dashboard is designed as a safe local demonstration and ML analytics application. It does not inspect real network packets, collect credentials, or require privileged packet-capture access.

If live packet capture is ever added in a future version, it should be treated as a separate acquisition layer rather than mixed with the existing model-evaluation results.
